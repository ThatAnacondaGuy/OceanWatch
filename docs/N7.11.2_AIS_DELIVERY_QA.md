# N-7.11.2 / N-7.11.3 AIS Delivery & API Contract QA

## Root Cause Analysis

### N-7.11.2: AIS Delivery Failure
The Vite `preview` server lacked a proxy block, causing `/api/` requests to return the SPA `index.html` instead of proxying to FastAPI. Fixed by adding `preview.proxy` to `vite.config.ts`.

### N-7.11.3: Missing `playback_asset` in API Response
The backend Python dict in `demo.py` line 144 had **incorrect indentation** (`"ais":` was indented 16 spaces instead of 8). While syntactically valid Python, this caused the `"ais"` key to serialize correctly but its `playback_asset` field was missing from the running server's cached response. The stale `__pycache__` bytecode was serving an older version of the dict that only contained `tracks_asset`.

**Fix:** Corrected indentation, added `"status": "synthetic_demo"` field, cleared `__pycache__`, and restarted the backend.

### N-7.11.3 Additional: Runtime `.toFixed()` crash
The AIS point schema in `ais_playback.json` has keys: `time`, `lat`, `lon`, `heading` — but **no `speed` field**. The VesselTrackingScreen called `p.speed.toFixed(1)` which crashed on `undefined`. Fixed by using `(p.speed ?? 0).toFixed(1)` and similar guards on all numeric render paths.
