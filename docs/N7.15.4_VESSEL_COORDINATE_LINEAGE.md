# Phase N-7.15.4: Definitive Vessel Coordinate Lineage Audit

## 1. Mismatch Discovery

An exhaustive trace of the coordinate lineage across `/api/demo/ennore`, `ais_playback.json`, `DashboardMap.tsx`, and `MapLibreMap.tsx` revealed the following critical bugs causing the geographic misalignment:

1. **Dual Competing Sources:** The frontend was utilizing two conflicting coordinate states simultaneously.
   - **`DashboardMap.tsx` (Markers):** Used the dynamic playback state from `ais_playback.json` via `getVesselStateAtTime()`.
   - **`DashboardMap.tsx` (fitBounds):** Hardcoded to use `v.position` (the static API state) to set the map zoom/center.
   - **`MapLibreMap.tsx` (Vessel Tracking):** Hardcoded to use `v.position` for both its markers and its bounding box.
   
2. **The "Inland" Optical Illusion:** Because the old bounding boxes were incorrectly computed (pulling in vessels up to 40km away), the map zoomed out drastically. This extreme scale caused the `SOURCE #1` marker to physically overlap inland map tiles (like Thervoy Kandigai) on the screen, creating the illusion that the vessel coordinate itself was inland, when in reality the map viewport was just drastically over-expanded.

3. **Vite Asset Caching:** The browser/Vite dev server aggressively cached `ais_playback.json`. Previous regeneration attempts failed to visually reflect because the frontend was still rendering the cached offshore coordinates from the original Gulf of Mexico import.

## 2. Canonical Lineage Resolution

We have now established ONE canonical source of truth for all synthetic vessel geography:

**Source:** `getVesselStateAtTime(vesselId, playbackTime, playbackData, ...)`
**Data Origin:** `ais_playback.json`

Code modifications applied:
- `DashboardMap.tsx` was patched so `fitBounds` dynamically calculates the bounding box using the actual `playbackTime` state, not the static API `v.position`.
- `MapLibreMap.tsx` (powering `/vessels` and others) was completely refactored to replace all instances of `.setLngLat([v.position.lon, v.position.lat])` with the dynamic `getVesselStateAtTime` calculation.
- The Vite server was hard-restarted (`pkill -f vite`) to obliterate the stale asset cache.
